# Mock Proxy Server

Node.js сервер, который:
- отдаёт **моковые** JSON-ответы для запросов, описанных в папке `mocks/`;
- все **остальные** запросы прозрачно проксирует на реальный бэкенд (`BACKEND_URL`).

## Установка

```bash
npm install
cp .env.example .env
# отредактируйте .env — укажите BACKEND_URL
npm start
```

Для авто-перезапуска при разработке:

```bash
npm run dev
```

## Настройка (.env)

| Переменная  | Описание                                      | По умолчанию |
|-------------|------------------------------------------------|--------------|
| BACKEND_URL | URL реального бэкенда для проксирования        | —            |
| PORT        | Порт мок-сервера                                | 4000         |
| MOCKS_DIR   | Папка с json-файлами моков                      | ./mocks      |
| VERBOSE     | Логировать в консоль мок/прокси-запросы         | true         |

## Формат мок-файла

Каждый файл в `mocks/` — это один объект мока или массив объектов:

```json
{
  "method": "GET",
  "url": "/api/users/1",
  "isRegex": false,
  "status": 200,
  "delay": 0,
  "headers": { "X-Custom": "value" },
  "payload": { "id": 1, "name": "Иван" }
}
```

Поля:
- **method** (обязательно) — HTTP метод: GET, POST, PUT, PATCH, DELETE...
- **url** (обязательно) — путь запроса. Поддерживаются три варианта:
  - точное совпадение: `"/api/users/1"`
  - wildcard в конце: `"/api/users/*"`
  - regexp (при `"isRegex": true`): `"^/api/users/\\d+$"`
- **status** — HTTP-код ответа мока (по умолчанию 200)
- **delay** — искусственная задержка ответа в мс (по умолчанию 0)
- **headers** — дополнительные заголовки ответа
- **payload** — тело JSON-ответа, которое вернёт мок

Один файл может содержать массив таких объектов (см. `mocks/orders.json`).

## Как это работает

1. На каждый входящий запрос сервер сначала ищет совпадение по `method` + `path` среди загруженных моков.
2. Если совпадение найдено — возвращается `payload` из мока (реальный бэкенд не вызывается).
3. Если совпадения нет — запрос прозрачно проксируется на `BACKEND_URL` (метод, заголовки, тело, query-параметры сохраняются), и клиенту возвращается настоящий ответ бэкенда.
4. Папка `mocks/` отслеживается на изменения (`chokidar`) — можно редактировать/добавлять json-файлы без перезапуска сервера.

## Примеры в комплекте

- `mocks/users.json` — точный путь `GET /api/users/1`
- `mocks/orders.json` — wildcard `GET /api/orders/*` и `POST /api/orders`, два мока в одном файле
- `mocks/products.json` — regexp `GET /api/products/\d+`

## Проверка

```bash
# Замокан:
curl http://localhost:4000/api/users/1

# Замокан (wildcard):
curl http://localhost:4000/api/orders/555

# Не замокан — уйдёт на реальный BACKEND_URL:
curl http://localhost:4000/api/anything-else
```
